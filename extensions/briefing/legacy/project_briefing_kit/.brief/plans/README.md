# 브리핑용 계획 문서 작성 가이드

이 폴더는 선택 사항이다. 일일 브리핑에서 계속 참고해야 하는 작업 목표나 구현 계획이 있을 때 Markdown 문서를 추가한다. 브리핑 담당자가 저장소 전체를 보지 못하더라도 다음 작업을 제안할 수 있도록, 결정된 목표와 현재 맥락을 짧고 구체적으로 기록한다.

`README.md` 자체는 활성 계획으로 취급하지 않는다.

## 권장 파일 구성

계획이 하나라면 `current.md`, 여러 개라면 `기능명.md`처럼 알아보기 쉬운 이름을 사용한다. 계획 문서에는 다음 구조를 권장한다.

```markdown
---
title: 계획 제목
status: active # active | planned | paused | done
updated: 2026-08-08
---

# 목표
- 이 계획으로 달성할 결과

## 완료 기준
- [ ] 검증 가능한 완료 조건

## 현재 상태
- 이미 끝난 작업과 확인 근거
- 최근 중단 지점

## 다음 작업
- [ ] 우선순위가 가장 높은 구체적인 작업
- [ ] 후속 작업

## 결정 및 제약
- 확정된 기술 결정, 범위 제외, 지켜야 할 조건

## 막힘 및 확인 사항
- 의존성, 미정 사항, 필요한 외부 결정

## 관련 경로
- 구현 파일, 문서, 테스트 또는 이슈 위치
```

## 관리 원칙

- 현재 실행할 계획은 `status: active`로 표시한다.
- 목표, 다음 작업 또는 결정이 달라지면 `updated`와 본문을 함께 갱신한다.
- 완료한 계획은 `status: done`으로 바꾸거나 저장소의 일반 문서로 옮긴다.
- 비밀번호, 토큰과 개인 정보 등 민감한 값은 기록하지 않는다.
