# 프로젝트 일일 작업 브리핑 지침

이 파일은 `05_ProjectContexts/<briefing_id>/.brief/brief.md`의 템플릿이다. 목표는 구현 상태를 진단하는 것이 아니라 Vault 작업 문서에서 오늘 할 일을 짧게 전달하는 것이다. 브리핑은 읽기 전용이다.

## 읽을 문서

- 우선 확인할 계획 문서:
- Task 또는 인계 문서:
- 프로젝트 고유 완료 기준:

## 선정 규칙

1. 활성 계획과 인계 문서에서 아직 완료되지 않은 작업을 찾는다.
2. 문서의 우선순위에 따라 오늘 완료 가능한 작업 1~3개만 고른다.
3. 문서에 기록된 완료 기준과 막힘만 전달한다.
4. 작업 문서가 없거나 서로 충돌하면 임의로 구현 범위를 만들지 말고 필요한 문서 갱신을 알린다.

외부 개발 저장소, README, 구현 코드, 테스트, Git 브랜치·커밋·dirty worktree는 조사하지 않는다. 다른 기기에서 생긴 구현 차이도 분석하지 않는다.

## 응답 내용

- 오늘 할 일 1~3개와 완료 기준
- 문서에 명시된 막힘·사용자 결정만 최대 2개(없으면 생략)
