# 웹훅·Discord·메일 연동 확장

상태: 설계 단계.

## 목적과 범위

등록된 조건으로 APS Server API를 호출하고 응답을 Discord·메일 등에 전달한다. 수신 요청에 응답하는 흐름과 예약/이벤트 조건에 따라 보내는 흐름을 모두 다룬다. 조건은 운영자가 등록한 대상·시간·이벤트·문서 종류·상태 필터로 제한한다.

Project 목록은 Core만으로 제공한다. `.brief` 요청은 확장 설치와 결과 가용성을 확인하고 새 생성이 필요하면 권한이 있는 고정 Job을 명시적으로 요청한다. Content GET에 생성 부작용을 추가하지 않는다. AI가 없어도 기본 목록 전달이 가능해야 한다.

## 작업

- [ ] **HOOK-01** — 구독/조건/대상 channel ID/허용 operation/응답 형식의 schema와 등록·수정·중지 계약 정의.
- [ ] **HOOK-02** — 수신 서명·timestamp·재전송 방지·채널 신원과 APS 역할 mapping 구현. channel ID만으로 operator 권한 부여 금지.
- [ ] **HOOK-03** — 목록·저장 briefing 조회와 비동기 생성 Job 접수·완료 응답 연결. 미설치·AI 비활성·결과 없음·실패 구분.
- [ ] **HOOK-04** — Discord/메일 adapter·전달 queue·중복 방지·재시도·속도 제한·실패 내역 구현. 전송 credential은 별도 secret으로 보관.
- [ ] **HOOK-05** — 등록 목적지 제한·SSRF 방어·출력/첨부 제한·민감 정보 제거 및 수신자별 문서 접근 권한 적용.
- [ ] **HOOK-06** — 시간 조건은 cron 재사용, 이벤트 조건은 검증된 Job 완료/Content 갱신에 연결. 미리보기·명시적 활성화·중지 후 재전송 차단 정의.

완료 조건: 등록 조건과 권한에 맞는 결과만 지정 채널에 전달하며 중복 이벤트·재시도의 반복 발송을 억제한다. 채널 장애가 Core API를 중단시키지 않는다.

선행: Core Content/Job 계약. `.brief`는 briefing 전달에만, AI 큐는 해당 생성 요청에만 필요하다.
